# Pi Lab 行为清单

编号按功能区分配字母前缀、区内顺序编号；端到端用户故事使用 `E2E` 前缀。优先级：P0 是坏了就无法完成核心调试，P1 是重要体验，P2 是细节打磨。状态「未验证」表示这条行为尚未由浏览器验收测试确认，不代表代码一定未实现。可测性：`mock` 可用模拟接口/流测试；`需真实模型` 会实际消耗模型额度；`需Pi CLI` 需要本机 Pi 及相应扩展/登录；`手动` 需要人工检查。除另有说明，每条操作从打开 Pi Lab 开始。

## 布局与导航（LAY）

### LAY-01 打开本机工作区
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 启动服务并打开网页。
2. 等待工作区加载。

**期望**
- 进入会话编辑器，可见会话列表、消息区、底部编辑框和模型工作台；加载中有状态提示。
- 工作区读取失败时显示错误和「重试」，不把错误页面误显示成空白会话。

### LAY-02 收起与展开侧栏
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 点击侧栏收起按钮，再点击展开按钮。
2. 在窄屏宽度下重复操作。

**期望**
- 收起时会话标题与操作隐藏，仍可用首字母切换会话；展开后恢复列表。
- 会话内容区不会被侧栏遮住或产生横向溢出。

### LAY-03 搜索会话
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 在侧栏输入标题、来源会话标题或工作目录片段。
2. 清空搜索，或输入一个不存在的词。

**期望**
- 匹配项随输入更新；清空后恢复完整列表；无匹配时显示「没有匹配的会话」。
- 过滤列表不删除或更改任何会话。

### LAY-04 新建、改名、复制和删除会话
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 点击新建会话，再按侧栏显示的 ⌘N 新建会话。
2. 修改标题并复制该会话。
3. 删除副本并确认；尝试取消另一会话的删除。
4. 删除最后一个会话。

**期望**
- 点击和 ⌘N 都能新建会话；新会话有默认系统指令。副本带有消息和配置、标题带「副本」，但没有运行记录。
- 删除前要求确认；取消不变更数据。删除当前会话后切换到剩余会话；删除最后一个后仍留下可用的新会话。

### LAY-05 切换工作台、主题和工具折叠
优先级: P2 · 可测性: mock · 状态: 未验证

**操作**
1. 分别隐藏/显示右侧工作台、切换浅色/深色主题、折叠/展开工具过程。
2. 刷新页面。

**期望**
- 三种开关互不影响；主题和工具折叠选择刷新后保留。
- 隐藏工作台不改变会话设置；重新显示时设置仍在。

### LAY-06 长对话滚动与窄屏
优先级: P1 · 可测性: 手动 · 状态: 未验证

**操作**
1. 打开含有许多长消息、代码块和工具步骤的会话。
2. 滚到旧消息，再运行一段较长的流式回复；随后使用回到底部按钮。
3. 将视口缩窄至手机宽度。

**期望**
- 贴近底部时新内容到达会跟随滚动；读旧消息时不被强制拉回底部，并可一键跳到顶部/底部。
- 长代码、链接和工具参数可在容器内阅读，不把页面撑出横向滚动；窄屏下工作台可单独打开和滚动。

## 对话编辑（MSG）

### MSG-01 添加带角色的消息
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 从底部选择 User、Assistant 或 System，输入内容后选择「仅添加」。
2. 在消息区的插入入口添加一条消息，并尝试从系统指令区添加 Developer。

**期望**
- 「仅添加」只把消息加入当前历史，不发起模型请求；插入消息出现在所选消息之后。
- 支持 system、developer、user、assistant、tool 五种历史角色；新消息默认启用，顺序可见。

### MSG-02 编辑、保存和取消消息
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 编辑一条已有消息并保存。
2. 再次编辑，修改文本后按 Esc。
3. 编辑时按 Cmd/Ctrl+Enter 保存。

**期望**
- 保存后的文本显示在原位置，并在下次运行作为上下文；取消恢复编辑前文本。
- 保存快捷键和按钮结果一致；多行文本、中文及长文本不丢失。

### MSG-03 更改消息角色
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 将普通 user 消息切换为 assistant、system 或 developer。
2. 对含有工具调用的 assistant 消息及 tool 结果尝试更改角色。

**期望**
- 普通消息可切换到可用角色，内容保留。
- 工具调用及其结果不能被直接改成普通消息角色，避免配对信息悄悄丢失；界面给出原因提示。

### MSG-04 临时排除消息
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 点击一条消息的眼睛按钮排除，再点击恢复。
2. 对工具调用或结果消息执行同样操作。

**期望**
- 排除消息仍显示在历史中但有明显区分，运行时不发送；恢复后重新纳入请求。
- 工具调用与配对结果作为一组同时启用或排除；被排除的消息不会改变原文。

### MSG-05 调整消息顺序
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 使用上移/下移按钮调整普通消息顺序。
2. 尝试把一组工具调用/结果拆开或移到不合法位置。

**期望**
- 合法调整立即显示并影响下一次请求；首条不能继续上移、末条不能继续下移。
- 会破坏工具配对的操作被拒绝并提示原因，消息次序不变。

### MSG-06 删除消息和工具步骤
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 删除普通消息。
2. 删除含调用的 assistant 消息、单个工具调用，或工具结果。

**期望**
- 普通消息只删除自身；删除工具步骤时，其配对结果/调用一起处理，不留下悬空 ID。
- 仍有其它工具调用或 assistant 正文时保留该 assistant 消息；变更影响下一次上下文，不会重放或撤销已执行操作。

### MSG-07 复制完整消息文本
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 对一条包含普通文字或多段内容的消息使用复制操作。
2. 将剪贴板内容粘贴到文本框；拒绝剪贴板权限后再试一次。

**期望**
- 剪贴板得到该消息的完整纯文本，不夹带角色按钮或 HTML；成功和失败均有明确反馈。

### MSG-08 搜索并跳转到消息
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 打开「目录」，搜索一段只出现在旧消息或工具摘要里的文字。
2. 点击结果，再搜索不存在的内容并按 Esc。

**期望**
- 搜索结果显示角色、摘要和序号；命中词高亮，点击后滚动到对应消息并短暂标记。
- 被折叠的系统指令/工具详情会展开到目标；无结果有空状态，Esc 关闭目录，搜索不改动原消息。

### MSG-09 阅读 Markdown、表格和代码块
优先级: P2 · 可测性: mock · 状态: 未验证

**操作**
1. 查看包含标题、列表、表格、代码块和链接的消息。
2. 复制代码块；再查看包含 HTML 标签或 `javascript:` 链接的消息。

**期望**
- 支持的 Markdown 以可读格式显示，表格和长代码可在各自区域滚动；复制代码只复制代码内容。
- 消息按纯文本安全渲染，不执行 HTML；仅 http、https、mailto 链接可点击。

## 模型与参数配置（MOD）

### MOD-01 切换协议和模型
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 打开模型工作台，切换接口协议并改模型 ID。
2. 切到另一会话再切回来。

**期望**
- 下一次运行使用新配置，旧消息不被改写；模型和协议按会话分别保存。
- Pi 订阅模式显示已配置登录的模型目录；自定义接口允许填写模型 ID。

### MOD-02 设置推理强度与 Temperature
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 为当前模型选择支持的推理档位，再切换到不支持该档位的模型。
2. 在推理关闭与开启时查看 Temperature 控件和请求参数。

**期望**
- 可选档位与当前模型能力相符，实际映射值可在请求检查中核对；切换模型时不支持的旧档位被调整并提示。
- 推理开启或使用 Pi 订阅时不发送 Temperature；关闭推理后自定义接口可设置 Temperature。

### MOD-03 配置 API Key 与密钥优先级
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 在自定义接口填写页面 API Key，并设置环境变量 Key 后运行。
2. 导出会话、刷新网页并检查项目工作区文件。

**期望**
- 页面 Key 优先于 `PI_LAB_API_KEY`，再优先于对应供应商变量；未提供时本机兼容接口可使用占位 Key。
- 页面 Key 不进入请求检查的鉴权头、localStorage、工作区文件或导出 JSON；刷新后页面 Key 清空。

### MOD-04 校验协议不支持的角色与位置
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 在 Anthropic 模式保留 Developer，或把 System 放到普通对话消息之后后运行。
2. 在 Pi 订阅模式尝试相同的 System 位置错误。

**期望**
- 运行前明确说明不支持的角色/位置；不发出模型请求、不偷偷改写角色或重排历史。
- 修正消息位置/角色或切换协议后，仍可用原消息再次运行。

### MOD-05 输出上限与 Agent 轮数
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 修改最大输出 Tokens 和最大 Agent 轮数，输入边界值与越界值。
2. 让模拟运行触发输出长度上限或轮数上限。

**期望**
- 最大输出为 1–128000；Agent 轮数为 1–50。无效值不能静默变成有效配置。
- 达到上限时保留已有内容和工具结果，运行记录标出对应状态；可再次运行继续。

### MOD-06 切换 Agent 工具模式
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 分别选择 Agent 和「关闭」后运行带工具调用历史的会话。
2. 观察当前请求中的工具声明。

**期望**
- Agent 模式启用 Pi Lab 工具；关闭模式不提供工具，但仍能回放完整的既有工具历史。
- 切换模式不删除历史工具调用，也不执行旧调用。

### MOD-07 设置工具工作目录
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 填写一个已存在的绝对路径并运行 Agent。
2. 清空路径，再填写相对路径或不存在的路径运行。

**期望**
- 有效路径用于工具运行；留空使用服务启动目录。
- Agent 模式下无效路径给出明确错误且不调用模型/工具；关闭工具模式时不要求本机工具目录。

### MOD-08 估算上下文 Tokens
优先级: P2 · 可测性: mock · 状态: 未验证

**操作**
1. 编辑消息、思考内容或工具参数，再排除一条消息。
2. 精简一组工具步骤并查看底部上下文计数。

**期望**
- 显示估算 Token 数，并按消息、思考和工具参数计算；排除的消息不计入将发送的上下文。
- 精简工具组后估算值及「已省」比例更新；数值是估算而非供应商的精确用量。

## 运行与流式输出（RUN）

### RUN-01 运行当前启用的上下文
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 编辑多条不同角色消息，排除其中一条，点击「重新运行」或使用运行快捷键。
2. 尝试在没有有效启用消息时运行。

**期望**
- 请求严格按可见顺序发送启用消息及当前参数；不添加隐藏 user 消息，不改写角色/文本。
- 空上下文被拒绝并提示「请先添加至少一条有内容且已启用的消息」，不生成空运行。

### RUN-02 发送快捷键和中文输入法
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 在底部编辑框按 Enter、Shift+Enter；使用中文输入法组字时按 Enter。
2. 将焦点放在消息编辑框，再按 Cmd/Ctrl+Enter。

**期望**
- Enter 发送并运行；Shift+Enter 换行；输入法确认候选时不意外发送。
- Cmd/Ctrl+Enter 不抢占输入框中的编辑快捷键；编辑框外可运行当前上下文。

### RUN-03 流式显示正文和思考内容
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 运行一个逐段返回正文、思考摘要和多条助手消息的模拟响应。
2. 收到内容时滚动到旧消息，再手动跳到底部。

**期望**
- 正文在到达时出现在对应助手消息，思考内容单独显示；不伪造打字或思考进度。
- 流结束后助手消息成为可编辑历史，运行中的状态指示消失；手动浏览旧内容时不被自动拉走。

### RUN-04 停止生成并保留已收到内容
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 启动持续流式输出的运行。
2. 收到部分正文后点击「停止」。

**期望**
- 请求被取消，运行记录为「已停止」，已收到的正文仍保留且可编辑。
- 如果助手占位消息没有正文、图片或工具调用，则移除空占位；停止不会被报告成模型成功。

### RUN-05 连接失败、模型失败与流中断
优先级: P0 · 可测性: mock · 状态: 未验证

**操作**
1. 分别模拟网页连不上本地服务、后端模型返回错误、已有部分正文后流突然断开。

**期望**
- 错误横幅区分本地服务连接失败与模型错误；保留可用的部分正文并显示具体原因。
- 中途断流显示「回复流连接意外中断」类提示；错误记录和诊断日志可查，不把失败当成完成。

### RUN-06 输出长度和轮数结束状态
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 模拟提供商达到输出上限；再模拟 Agent 达到最大轮数。
2. 打开运行记录并再次运行。

**期望**
- 界面分别提示输出未完成和 Agent 轮数已满；已生成内容、工具轨迹及对应状态均保存。
- 用户可检查后重新运行；不会丢弃已完成的工具结果。

### RUN-07 运行期间的重复操作与 Assistant 续写
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 流尚未结束时再次点击运行、发送消息或尝试编辑/切换会话。
2. 让会话以 Assistant 消息结尾后再次运行。

**期望**
- 同一页面同一时刻只有一个主运行；运行期间阻止重复请求和破坏上下文的编辑/切换。
- Assistant 结尾运行时以现有历史发起下一次生成，不插入合成 user 消息；不支持该上下文的供应商错误应原样可见。

## 工具调用展示（TOOL）

### TOOL-01 展示工具调用和配对结果
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 使用模拟流返回一条带正文的工具调用、工具结果及后续助手回复。
2. 折叠和展开工具步骤。

**期望**
- 正文不随工具步骤折叠而消失；每个步骤显示工具名、执行状态和配对结果。
- 成功、失败、待返回状态有区别；多步骤顺序与实际轨迹一致。

### TOOL-02 查看和编辑原始工具数据
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 展开工具步骤的原始参数，修改工具名、Call ID、参数 JSON、结果及错误标记。
2. 将参数改成无效 JSON 或造成重复 Call ID 后运行。

**期望**
- 编辑内容与工具调用/结果配对一致更新；无效 JSON、缺失结果或重复 ID 在运行前明确报错。
- 修改历史只影响下一次上下文，不重新执行已保存的调用。

### TOOL-03 精简工具上下文并恢复原文
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 精简一组已完成工具步骤，查看并编辑摘要。
2. 再次运行后还原该组。

**期望**
- 摘要留在模型上下文，原始参数/结果仍可在界面检查；同组调用与结果一并精简。
- 还原后下一次请求重新包含原始内容；未完成工具组不能被精简。

### TOOL-04 中断正在执行的工具
优先级: P1 · 可测性: mock · 状态: 未验证

**操作**
1. 让模拟工具执行停留在进行中。
2. 点击停止并检查消息历史和运行轨迹。

**期望**

- 每个工兵有独立上下文和 Pi 进程；创建/发消息默认接受后立即返回，不阻塞主会话。
- 名字重复和无 Codex 登录/模型时明确失败；等待可指定 1–8 个会话，取消等待不停止工兵，读取已交付回复不会重复当作新回复。

## 终端 Pi 扩展（CLI）

### CLI-01 安装与启用扩展
优先级: P1 · 可测性: 需Pi CLI · 状态: 未验证

**操作**
1. 安装/更新 Pi GPT 扩展或实时同步扩展。
2. 新开 Pi 会话；对已打开会话执行 `/reload`。

**期望**
- 新进程加载扩展，已打开进程重载后可用；`--no-extensions` 模式不宣称同步可用。
- 安装失败给出可见错误，不改动 Pi 登录信息或模型配置。

### CLI-02 在终端用命令管理 GPT 会话
优先级: P1 · 可测性: 需Pi CLI · 状态: 未验证

**操作**
1. 在 Pi 终端使用 `/gpt list`、`new`、`read`、`send`、`after`、`replace`、`stop`、`close` 或 `reply`。
2. 让回复超过显示长度，或让 GPT 提出待回答问题。

**期望**
- 名字可含空格；send/after/replace 的排队和中断语义清楚；多问题回答可指定序号。
- list/read 不重放旧回复；原始日志按需查看；停止 GPT 与停止主模型是两个独立操作。

### CLI-03 Pi 原生上下文修改的持久性
优先级: P1 · 可测性: 需Pi CLI · 状态: 未验证

**操作**
1. 在网页编辑并应用 Pi 会话上下文。
2. 在终端继续提问，再恢复该会话或切换分支。

**期望**
- 修改作为当前 Pi 会话分支的附加记录恢复；终端显示的原始消息仍保留。
- 遇到 developer 角色、前缀冲突或压缩冲突时明确拒绝/暂停，不丢弃图片、工具声明和原生元数据。

## 端到端场景（E2E）

### E2E-01 修改提示并比较两个分支
优先级: P0 · 可测性: mock · 状态: 已验证

**操作**
1. 输入一段提示并运行，等待模拟模型回复。
2. 从用户消息处分支，在新分支改写提示并再次运行。
3. 交替打开两个分支和运行记录。

**期望**
- 两次请求各自带正确提示和同一份必要前缀；分支后续编辑互不影响。
- 每次模型、状态和输出归属正确；源会话仍能恢复原文。

### E2E-02 找出协议错误并修正后运行
优先级: P1 · 可测性: mock · 状态: 已验证

**操作**
1. 选择 Anthropic，添加独立 Developer 或把 System 放在对话中间并运行。
2. 按错误提示修正角色/顺序，再运行并打开请求检查。

**期望**
- 第一次运行在发请求前被拒绝，历史原样保留；修正后请求体角色与顺序可核对。

### E2E-03 并行派发 GPT 并审阅结果
优先级: P1 · 可测性: 需真实模型 · 状态: 未验证

**操作**
1. 让主模型创建两个不同名字的 GPT 工兵，派发相互独立的任务。
2. 继续与主模型交流，等待工兵交卷，再选择自动唤醒或手动审阅。

**期望**
- 派发后主会话可继续；两个工兵独立工作并显示状态。
- 主模型读取新回复后汇总完成、失败和待决策项；不会重复读取旧回复或因主模型中断而误报工兵已停止。

### E2E-04 修改网页中的 Pi CLI 历史并继续提问
优先级: P1 · 可测性: 需Pi CLI · 状态: 未验证

**操作**
1. 从网页选择一个空闲 Pi CLI 会话，编辑一条历史消息并应用。
2. 在同一个终端继续提问，再让 Pi 新增一条消息后回到网页。

**期望**
- Pi 后续模型请求使用已应用的修改，终端原始日志仍保留。
- 新消息被实时同步；网页没有未提交编辑时显示一致上下文，有草稿时不静默覆盖。

### E2E-05 准备图片、看图并刷新恢复
优先级: P1 · 可测性: 需真实模型 · 状态: 未验证

**操作**
1. 让 GPT 工兵提交一组具名图片，要求主模型查看总览并点名一张看细节。
2. 将图片结果留在会话中，刷新网页后再次打开。

**期望**
- Gemini 收到有编号的总览，细节请求只包含点名图片；网页工具结果可打开大图。
- 刷新后图片引用仍能显示；会话 JSON 只含项目内引用，原图保存在项目图片库。
